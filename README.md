# stegacrypt

[![CI](https://github.com/devilnevecry/stegacrypt/actions/workflows/ci.yml/badge.svg)](https://github.com/devilnevecry/stegacrypt/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.9%2B-blue)
![License](https://img.shields.io/badge/license-GPL--3.0-green)

Консольная утилита, которая **шифрует сообщение открытым ключом получателя и прячет его в PNG-картинке**.
Снаружи это обычная картинка, а прочитать сообщение сможет только владелец закрытого ключа.

```text
сообщение ──AES-256-GCM──▶ шифртекст ─┐
случайный ключ AES ──RSA-OAEP──▶ обёрнутый ключ ─┴▶ нагрузка ──LSB──▶ secret.png
```

## Возможности

- **Гибридное шифрование:** сообщение шифруется AES-256-GCM, а его ключ — RSA-OAEP (SHA-256). Длина сообщения ограничена только размером картинки.
- **Проверка целостности:** если данные в картинке изменили или повредили, расшифровка не пройдёт, а не выдаст мусор.
- **Незаметные изменения:** прячутся только младшие биты цветовых каналов (каждый канал меняется максимум на 1 из 255), биты равномерно разнесены по всему изображению. Альфа-канал и ICC-профиль сохраняются.
- **Защита ключей:** закрытый ключ шифруется паролем и сохраняется с правами `0600`, ключи слабее RSA-2048 отклоняются.
- **Безопасные умолчания:** ничего не перезаписывается без `--force`, а JPEG на выходе запрещён (он разрушил бы данные).
- Любой формат на входе, который понимает Pillow (PNG, JPEG, BMP, WebP, GIF — первый кадр), на выходе всегда PNG.

## Установка

Нужен Python 3.9 или новее.

```bash
git clone https://github.com/devilnevecry/stegacrypt.git
cd stegacrypt
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install .
```

После установки доступна команда `stegacrypt` (а также `python -m stegacrypt`).

## Быстрый старт

Боб хочет получать секретные сообщения от Алисы.

**1. Боб создаёт ключи**

```console
$ stegacrypt keygen bob
Пароль для закрытого ключа:
Повторите пароль:
Закрытый ключ (никому не показывайте): bob_private.key
Открытый ключ (его можно отправлять):  bob_public.key
```

`bob_public.key` Боб отправляет Алисе любым способом: он не секретный. `bob_private.key` остаётся только у Боба.

**2. Алиса прячет сообщение в картинке**

```console
$ stegacrypt encrypt -i examples/cover.jpeg -k bob_public.key -o secret.png -m "Встречаемся в полночь"
Готово: 40 байт сообщения спрятано в secret.png (в изображении 458 байт).
Отправляйте файл как есть: мессенджеры, которые пережимают картинки, разрушают данные.
```

**3. Боб достаёт сообщение**

```console
$ stegacrypt decrypt -i secret.png -k bob_private.key
Пароль для bob_private.key:
Встречаемся в полночь
```

Чтобы Боб тоже мог отвечать Алисе, ей нужно создать свои ключи (`stegacrypt keygen alice`) и отправить ему `alice_public.key`.

> Отправляйте `secret.png` **как файл или документ**. Мессенджеры, которые пережимают картинки («отправить как фото»), разрушают спрятанные данные.

## Команды

| Команда | Что делает |
|---|---|
| `stegacrypt keygen ИМЯ` | Создаёт `ИМЯ_private.key` и `ИМЯ_public.key`. Опции: `--bits` (по умолчанию 3072, минимум 2048), `--out-dir`, `--no-passphrase`, `--force`. |
| `stegacrypt encrypt -i КАРТИНКА -k ОТКРЫТЫЙ_КЛЮЧ -o РЕЗУЛЬТАТ.png` | Шифрует и прячет сообщение. Текст берётся из `-m "..."`, из файла `-f ФАЙЛ`, из stdin (`echo hi \| stegacrypt encrypt ...`) или вводится в ответ на запрос. |
| `stegacrypt decrypt -i КАРТИНКА -k ЗАКРЫТЫЙ_КЛЮЧ` | Достаёт и расшифровывает сообщение. С `-o ФАЙЛ` записывает его в файл (так можно получить и не-текстовые данные). |
| `stegacrypt capacity КАРТИНКА [-k ОТКРЫТЫЙ_КЛЮЧ]` | Показывает, сколько данных помещается в картинку. |

Подробнее: `stegacrypt --help` и `stegacrypt КОМАНДА --help`.

### Пароль от закрытого ключа

По умолчанию пароль запрашивается интерактивно. Для скриптов его можно передать переменной окружения `STEGACRYPT_PASSPHRASE`, но учтите, что переменные окружения могут быть видны другим процессам и попадать в историю оболочки.

## Сколько можно спрятать

Картинка вмещает по 3 бита на пиксель за вычетом 4 байт заголовка. Из этого ещё вычитаются служебные данные шифрования: около 420 байт для ключа 3072 бит и около 290 байт для 2048 бит.

| Размер картинки | Вместимость |
|---|---|
| 800 × 600 | ≈ 180 КБ |
| 1920 × 1080 | ≈ 778 КБ |
| 3840 × 2160 | ≈ 3,1 МБ |

Для обычных текстовых сообщений хватит и небольшой картинки. Точные цифры для вашей пары «картинка + ключ» покажет `stegacrypt capacity`.

## Безопасность и ограничения

Что защищено:

- **Конфиденциальность и целостность** сообщения: AES-256-GCM с новым случайным ключом на каждое сообщение, ключ обёрнут RSA-OAEP.
- **Закрытый ключ** хранится в зашифрованном виде и с ограниченными правами.

Чего утилита **не** делает:

- **Не скрывает факт передачи от специалиста.** LSB-стеганография обнаруживается статистическим анализом (стегоанализом). Защищает содержимое шифрование, а картинка лишь делает передачу менее заметной на первый взгляд.
- **Не подтверждает отправителя.** Любой, кто знает открытый ключ Боба, может создать сообщение, будто бы от Алисы. Подписей в формате пока нет.
- **Не даёт прямой секретности (forward secrecy).** Если закрытый ключ Боба утечёт, прочитаны будут и все старые сообщения, которые у кого-то сохранились.
- **Не переживает пережатие картинки.** Изменение размера, конвертация в JPEG, фильтры и пережатие мессенджерами уничтожают данные.
- **Не проходила независимый аудит.** Для серьёзных задач используйте проверенные инструменты (например, [age](https://github.com/FiloSottile/age) или GnuPG).

Закрытые ключи нельзя коммитить: `*.key` добавлен в `.gitignore`.

## Формат данных

Для любопытных и для тех, кто захочет написать совместимую реализацию. Все числа big-endian.

**В изображении (LSB в каналах R, G, B, по одному биту на канал):**

| Что | Где |
|---|---|
| Длина нагрузки в байтах, 32 бита | первые 32 канала |
| Биты нагрузки | с шагом `(всего_каналов − 32) // (8 × длина)`, начиная с 32-го канала |

**Нагрузка:**

| Поле | Размер |
|---|---|
| Магия `SGC` | 3 байта |
| Версия формата (сейчас 1) | 1 байт |
| Длина обёрнутого ключа AES | 2 байта |
| Обёрнутый ключ AES (RSA-OAEP, SHA-256) | размер ключа RSA |
| Nonce | 12 байт |
| Шифртекст + тег GCM | длина сообщения + 16 байт |

Всё до nonce передаётся в GCM как AAD.

## Использование как библиотеки

```python
from stegacrypt import core

core.hide("cover.jpeg", "bob_public.key", "Привет!".encode(), "secret.png")
message = core.reveal("secret.png", "bob_private.key", passphrase=b"пароль")
print(message.decode())
```

## Переход с версии 1.x

Версия 2.0 несовместима с прежним форматом, потому что раньше данные писались в красный канал первых строк картинки без шифрования ключа AES и без проверки целостности.

- **Ключи остаются рабочими:** формат PEM тот же, `*_private.key` и `*_public.key` из 1.x подходят без изменений.
- **Старые картинки версией 2 не читаются.** Для них используйте прежнюю версию (см. тег `v1.0` в репозитории).
- Скрипты `encrypt.py`, `decrypt.py` и `key_manager.py` заменены командами `stegacrypt encrypt`, `stegacrypt decrypt` и `stegacrypt keygen`.
